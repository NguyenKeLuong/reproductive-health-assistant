TÀI LIỆU CHI TIẾT KỸ THUẬT HỆ THỐNG TRỢ LÝ ẢO SỨC KHỎE SINH SẢN
(REPRODUCTIVE HEALTH ASSISTANT - MULTI-AGENT, MULTIMODAL & VOICE SYSTEM)
================================================================================

1. TỔNG QUAN DỰ ÁN & MỤC TIÊU
------------------------------
- Tên hệ thống: Trợ lý Virtual Sức khỏe Sinh sản Đa tác nhân & Đa phương thức (Reproductive Health Assistant).
- Mục tiêu: Cung cấp thông tin giáo dục y khoa, tư vấn sức khỏe sinh sản, bệnh lây truyền qua đường tình dục (STI/STD), biện pháp tránh thai, an toàn tình dục và chăm sóc tâm lý một cách chuyên sâu, chính xác, bảo mật và không phán xét.
- Mô hình hoạt động: Mô hình Client-Server đa giao diện (Web SPA React/TypeScript, CLI Rich Terminal) kết hợp với Backend FastAPI, hệ thống RAG nâng cao, Multimodal VLM và luồng xử lý âm thanh thời gian thực (Real-time Voice Calling).

1.1 KIẾN TRÚC AI AGENTIC & ĐA PHƯƠNG THỨC (AGENTIC & MULTIMODAL ARCHITECTURE)
-----------------------------------------------------------------------------
Hệ thống được thiết kế theo chuẩn Agentic AI hiện đại, vượt xa mô hình chatbot thông thường:
- Tư duy & Điều hướng (Reasoning & Dynamic Routing): Sử dụng Coordinator Agent để phân tích ngữ cảnh, ý định người dùng và tự động điều hướng câu hỏi đến các Agent chuyên gia bằng cơ chế LLM Tool-Calling.
- Giao thức MCP (Model Context Protocol): Xây dựng Server FastMCP cho phép đóng gói toàn bộ các Agent thành các "MCP Tools" tiêu chuẩn, giúp hệ thống dễ dàng kết nối và mở rộng với các máy chủ bên ngoài (Claude Desktop, ứng dụng di động...).
- Phân tích hình ảnh cận cảnh (Multimodal VLM): Tích hợp mô hình Vision-Language (Llama 3.2 11B Vision Instruct) cho phép phân tích hình ảnh tổn thương da liễu/sinh dục và xuất Báo cáo Phân tích Lâm sàng Sơ bộ.
- Cuộc gọi thoại thời gian thực (Real-time Voice Call): Kết nối WebSocket hai chiều cho phép hội thoại 1-1 bằng giọng nói với khả năng nhận diện ngắt lời (Interruption Detection), chuyển đổi âm thanh chuẩn WAV, STT 3 tầng và TTS 2 tầng.
- RAG hai giai đoạn (Two-Stage RAG): Tích hợp Qdrant Vector Database local kết hợp với Nvidia Reranker (Mistral 4B) và quy trình đánh giá chuẩn RAGAS.

2. KIẾN TRÚC HỆ THỐNG (ARCHITECTURE)
------------------------------------
Hệ thống gồm 3 tầng chính:

A. Tầng Giao diện Máy khách (Client Layer):
   1. Modern Web Application (health-chat-companion/): Ứng dụng Single Page Application (SPA) xây dựng trên React 18, TypeScript, Vite, Tailwind CSS, Lucide Icons. Hỗ trợ giao diện Chat Real-time, tải ảnh phân tích VLM và bộ điều khiển Cuộc gọi Voice Call 1-1.
   2. CLI Terminal (chatbot.py): Giao diện dòng lệnh mượt mà sử dụng thư viện Rich của Python dành cho người dùng thích trải nghiệm terminal.

B. Tầng Máy chủ Đầu não (Backend Layer - main.py & nvidia_service.py):
   - Server FastAPI ASGI đóng vai trò đầu não xử lý logic.
   - Quản lý đồng thời RESTful API (`/chat`), WebSocket Chat Streaming (`/ws/chat`), và WebSocket Voice Call (`/ws/voice-call`).
   - Tích hợp Nvidia NIM Cloud API (Llama 3.2 11B Vision, Llama 3.1 8B Instruct, Parakeet ASR, Mistral Reranker) kết hợp với các mô hình Local Hugging Face (Faster-Whisper, MMS-TTS VITS).

C. Tầng Lưu trữ & Dữ liệu Tri thức (Data Layer):
   - Qdrant Vector Database Local: Lưu trữ cơ sở dữ liệu tri thức y khoa đã được embedding.
   - File System / Local Cache: Lưu trữ các mô hình Hugging Face local (Faster-Whisper base/tiny, MMS-TTS-Vie).

3. CHI TIẾT CÁC THÀNH PHẦN AGENT & REGISTRY
--------------------------------------------
Hệ thống sở hữu 1 Coordinator Agent và 5 Specialist Agents (Agent Chuyên gia):

1. CoordinatorAgent (Agent Điều phối):
   - Vai trò: Phân tích câu hỏi người dùng, đối chiếu với Schema JSON của 5 Agent chuyên gia và thực hiện gọi hàm (Function Calling) để chọn Agent phù hợp nhất.
   - Nguyên tắc: Ép buộc chọn đúng 1 Agent chuyên gia duy nhất; truyền nguyên văn câu hỏi người dùng vào tham số `question`.

2. GeneralHealthAgent (anatomy_agent - Sức khỏe chung & Giải phẫu):
   - Vai trò: Tư vấn vệ sinh cá nhân, giải phẫu cơ quan sinh dục nam/nữ, quá trình dậy thì, sinh lý học (rụng trứng, xuất tinh) và sức khỏe tổng quát.

3. STIAgent (sti_agent - Bệnh lây truyền qua đường tình dục):
   - Vai trò: Chuyên sâu về HIV/AIDS, lậu, giang mai, sùi mào gà (HPV), herpes (HSV-1, HSV-2), viêm gan B/C, trùng roi...
   - Nội dung: Triệu chứng lâm sàng, đường lây nhiễm, biện pháp phòng ngừa (bao cao su, PrEP, PEP, vắc-xin), quy trình xét nghiệm và định hướng điều trị.

4. ContraceptionAgent (contraception_agent - Biện pháp tránh thai & Kế hoạch hóa):
   - Vai trò: Tư vấn các giải pháp tránh thai an toàn và kế hoạch hóa gia đình.
   - Nội dung: Thuốc tránh thai hàng ngày/khẩn cấp, đặt vòng tránh thai (IUD), cấy que, bao cao su nam/nữ, tính chu kỳ an toàn, hiệu quả và tác dụng phụ.

5. ReproductiveHealthAgent (reproductive_health_agent - Sức khỏe sinh sản):
   - Vai trò: Tư vấn chu kỳ kinh nguyệt, khả năng thụ thai, chăm sóc thai kỳ, đa nang buồng trứng (PCOS), lạc nội mạc tử cung, mãn kinh và sức khỏe sinh sản nam/nữ.

6. SafetyConsentAgent (safety_consent_agent - An toàn, Đồng thuận & Tâm lý):
   - Vai trò: Tư vấn sự đồng thuận (Consent), ranh giới cá nhân, nhận biết dấu hiệu lạm dụng/bạo lực tình dục, sức khỏe tâm lý trong mối quan hệ. Cung cấp đường dây nóng hỗ trợ khủng hoảng.

4. LUỒNG XỬ LÝ ÂM THANH TRỰC TIẾP (REAL-TIME AUDIO STREAM & VOICE CALL)
------------------------------------------------------------------------
Hệ thống hỗ trợ giao tiếp giọng nói hai chiều trực tiếp qua WebSocket endpoint `/ws/voice-call`. Quy trình xử lý âm thanh diễn ra theo các bước nghiêm ngặt:

4.1 Thu âm & Truyền tải (Audio Capture & Transport):
   - Client sử dụng Web API `navigator.mediaDevices.getUserMedia` bắt luồng âm thanh từ micro.
   - Mã hóa âm thanh thành các gói nhỏ (chuẩn WebM/Opus) và gửi liên tục lên Server qua WebSocket dưới dạng Base64 JSON (`type: "audio_chunk"`).

4.2 Phát hiện ngắt lời & Khai báo phát biểu (VAD & Interruption Detection):
   - Ngắt lời thời gian thực (Interruption): Nếu người dùng nói đè hoặc nhấn nút ngắt cuộc gọi, Client gửi gói tin `type: "interrupt"`. Server lập tức kiểm tra và hủy tác vụ sinh phản hồi giọng nói đang chạy (`active_task.cancel()`), dọn dẹp bộ đệm âm thanh (`audio_chunks = []`) và đưa trạng thái về `idle`.
   - Kết thúc phát biểu: Client phát hiện khoảng lặng hoặc người dùng thả nút nói, gửi gói `type: "speech_done"`. Server chốt bộ đệm và bắt đầu xử lý.

4.3 Tiền xử lý & Chuyển đổi định dạng âm thanh (Audio Preprocessing):
   - Server nối toàn bộ các mảng byte âm thanh nhận được trong lượt nói.
   - Sử dụng tiến trình ngầm `ffmpeg` (`convert_to_wav`) tự động chuyển đổi âm thanh từ bất kỳ định dạng nào (WebM, Opus, Ogg) thành định dạng chuẩn 16kHz Mono PCM WAV.

4.4 Luồng Nhận dạng Tiếng nói (Speech-to-Text - STT Pipeline 3 Tầng):
   - Tầng 1 (Primary): Chạy local mô hình Hugging Face Faster-Whisper (`WhisperModel` - bản `base` hoặc fallback `tiny` định dạng `int8` trên CPU). Nhận dạng tiếng Việt chính xác cao, chịu được tạp âm.
   - Tầng 2 (Fallback 1): Thư viện Python `speech_recognition` gọi Google Web Speech API (ngôn ngữ `vi-VN`).
   - Tầng 3 (Fallback 2): Gọi Nvidia NIM ASR Cloud API với mô hình `nvidia/parakeet-ctc-0.6b-vi`.

4.5 Xử lý Phản hồi LLM/VLM cho Cuộc gọi Voice:
   - System Prompt đóng vai Bác sĩ Da liễu & Sức khỏe Sinh sản tư vấn 1-1 trực tiếp qua điện thoại.
   - Ràng buộc đầu ra: Trả lời ngắn gọn (3-4 câu), ngôn ngữ tự nhiên, thấu cảm. **Tuyệt đối không dùng ký tự Markdown** (như `**`, `#`, danh sách số) để đảm bảo bộ tổng hợp giọng nói (TTS) đọc trôi chảy.

4.6 Luồng Tổng hợp Giọng nói (Text-to-Speech - TTS Pipeline 2 Tầng):
   - Tầng 1 (Primary Local TTS): Mô hình Hugging Face VITS Speech Synthesis (`facebook/mms-tts-vie`). Chạy suy luận PyTorch trong Thread Pool (`asyncio.to_thread`) để tránh làm nghẽn Event Loop của FastAPI ASGI. Chuyển đổi waveform `float32` thành mảng byte PCM WAV 16-bit.
   - Gửi âm thanh phản hồi: Mã hóa WAV byte thành Base64 và gửi về Client qua WebSocket (`type: "audio_response"`).
   - Tầng 2 (Fallback Client TTS): Nếu backend TTS gặp lỗi, Server phát tín hiệu để Client tự phát âm thanh bằng Web Speech API (`window.speechSynthesis`).

5. KIẾN TRÚC RAG & TÌM KIẾM VECTOR (RETRIEVAL-AUGMENTED GENERATION)
--------------------------------------------------------------------
Để đảm bảo thông tin y khoa chính xác, hệ thống triển khai giải pháp RAG nâng cao:

5.1 Cơ sở dữ liệu tri thức (Knowledge Base):
   - Nguồn dữ liệu: Bài báo y khoa lâm sàng tiếng Việt và tiếng Anh (được dịch/chuẩn hóa) về sức khỏe sinh sản, bệnh học, tránh thai, phụ khoa, nam khoa.
   - File nhúng: `knowledge_base_embedded.json` được chuẩn bị sẵn vector embedding.

5.2 Vector Database (Qdrant Local):
   - Sử dụng Qdrant Client chạy chế độ local (lưu file trực tiếp tại thư mục `./qdrant_data`).
   - Collection name: `reproductive_health_kb`.
   - Metric khoảng cách: Cosine Similarity.

5.3 Kỹ thuật Tìm kiếm & Reranking 2 Giai đoạn (Two-Stage Retrieval & Reranking):
   - Giai đoạn 1 (Vector Search): Truy vấn Qdrant để tìm Top 30 bài viết có khoảng cách Cosine gần nhất (`TOP_K_RETRIEVAL = 30`).
   - Giai đoạn 2 (Cross-Encoder Reranking): Gửi danh sách 30 bài viết và câu hỏi người dùng tới Nvidia Reranking API với mô hình `nv-rerank-qa-mistral-4b:1`. Chấm điểm lại mức độ liên quan và trích xuất Top 10 / Top 5 bài viết chuẩn xác nhất (`TOP_N_RERANK`).
   - Cơ chế xử lý sự cố: Tích hợp Exponential Backoff Retry tự động xử lý khi gặp lỗi Rate Limit API (HTTP 429).

5.4 Đánh giá Chất lượng RAG (RAG Evaluation Framework):
   - Sử dụng bộ dữ liệu kiểm thử 850 câu hỏi y khoa (`rag_test_dataset_850.json` & `rag_test_dataset_embedded.json`).
   - Đo lường hiệu năng tìm kiếm với chỉ số: Hit Rate @1, @3, @5, @10 và MRR (Mean Reciprocal Rank).
   - Đánh giá chất lượng sinh bằng RAGAS Framework dựa trên 4 tiêu chí: Faithfulness (Tính trung thực), Answer Relevancy (Độ liên quan câu trả lời), Context Recall (Độ gợi nhớ ngữ cảnh), và Context Precision (Độ chính xác ngữ cảnh).

6. XỬ LÝ MULTIMODAL VLM (PHÂN TÍCH HÌNH ẢNH LÂM SÀNG)
------------------------------------------------------
Hệ thống cho phép người dùng gửi hình ảnh tổn thương vùng da nhạy cảm hoặc cơ quan sinh dục qua giao diện Web WebSocket (`/ws/chat`) hoặc Voice Call (`/ws/voice-call`).

- Mô hình VLM: `meta/llama-3.2-11b-vision-instruct` (Nvidia NIM API), tự động fallback về `meta/llama-3.1-8b-instruct` nếu mô hình Vision bận.
- Logic phản hồi 2 trường hợp:
  1. Trường hợp chẩn đoán (Người dùng gửi ảnh kèm câu hỏi "đây là bị gì?", "chẩn đoán giúp tôi"...): 
     Mô hình xuất Báo cáo Phân tích Lâm sàng Sơ bộ theo định dạng Markdown:
     - 🏥 BÁO CÁO PHÂN TÍCH LÂM SÀNG SƠ BỘ
     - Bệnh lý nghi ngờ (Suspected Condition - Tên Việt & Latinh)
     - Vùng da / Niêm mạc bị ảnh hưởng
     - Hình thái tổn thương (Màu sắc, mật độ, mụn nước, vết loét...)
     - Kích thước & Sự phân bố
     - Cơ chế bệnh sinh & Tác nhân (Virus HPV, HSV, vi khuẩn...)
     - Khuyến nghị y tế (Chuyên khoa khám, Xét nghiệm cần thiết, Lưu ý an toàn)
  2. Trường hợp trò chuyện/tâm lý ("tôi lo lắng quá", "có nguy hiểm không bác sĩ"...):
     Mô hình trò chuyện thấu cảm, giải đáp lo lắng một cách tự nhiên mà không dùng cấu trúc báo cáo cứng nhắc.

7. GIAO THỨC MCP (MODEL CONTEXT PROTOCOL)
------------------------------------------
Tệp `mcp_sever.py` triển khai máy chủ FastMCP chuẩn giao thức MCP:
- Tên MCP Server: `SexualHealthAssistant`.
- Danh sách MCP Tools cung cấp:
  1. `coordinator(question)`: Tự động điều hướng câu hỏi đến Agent phù hợp nhất.
  2. `general_health_agent(question)`: Tư vấn sức khỏe chung, giải phẫu, dậy thì.
  3. `sti_agent(question)`: Tư vấn các bệnh lây qua đường tình dục.
  4. `contraception_agent(question)`: Tư vấn biện pháp tránh thai & kế hoạch hóa.
  5. `reproductive_health_agent(question)`: Tư vấn sức khỏe sinh sản, kinh nguyệt, thai kỳ.
  6. `safety_consent_agent(question)`: Tư vấn an toàn, đồng thuận, tâm lý mối quan hệ.
- Ứng dụng: Cho phép tích hợp hệ thống làm công cụ (Tool) trực tiếp cho Claude Desktop hoặc bất kỳ máy chủ MCP Client nào.

--------------------------------------------
- Ngôn ngữ lập trình: Python 3.13+
- Backend Framework: FastAPI (ASGI Framework hiệu năng cao).
- Web Server ASGI: Uvicorn.
- Cổng kết nối (Port): 8010.
- Endpoints chính:
  * `POST /chat`: REST API tư vấn chat ngắn.
  * `WS /ws/chat`: WebSocket Chat Real-time Streaming & VLM Image Analysis.
  * `WS /ws/voice-call`: WebSocket Real-time Voice Call (VAD, Interruption, STT/TTS).
- Mô hình LLM / VLM:
  * Primary Text LLM: Gemma 4 31B Instruct / Llama 3.1 70B Instruct / SaoLa4-medium / Llama 3.1 8B Instruct (Nvidia NIM & FPT Cloud).
  * Vision VLM: Meta Llama 3.2 11B Vision Instruct.
  * Reranker: Nvidia Rerank QA Mistral 4B (`nv-rerank-qa-mistral-4b:1`).
- Mô hình Local AI (Offline/On-Device):
  * STT Local: Faster-Whisper (`WhisperModel` base/tiny int8 CPU).
  * TTS Local: Hugging Face VITS (`facebook/mms-tts-vie` via PyTorch).
- Database Vector: Qdrant Client Local (Cosine Distance).
- Frontend Web App: React 18, TypeScript, Vite, Tailwind CSS, Lucide Icons.
- Frontend CLI App: Python Rich Terminal UI (`chatbot.py`).
- Đóng gói & Triển khai: Docker, Docker Compose (`Dockerfile`, `docker-compose.yml`).

     * Emotional (Tâm lý, an toàn consent): 1 câu (0.12%)
   - Cấu trúc Test Case: `id`, `metadata` (`question_type`), `retrieval_ground_truth` (`source_file`, `golden_chunk`), `generation_ground_truth` (`user_query`, `expected_answer`, `evaluation_criteria`), `user_query_embedding` (1024/1536 dim Qwen3 FP16).

11. KẾT QUẢ ĐÁNH GIÁ & BẢNG XẾP HẠNG BENCHMARK (EVALUATION & LEADERBOARD)
